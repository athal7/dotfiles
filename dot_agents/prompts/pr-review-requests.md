Find GitHub pull requests for which the authenticated user currently has an outstanding review request, then create or resume one AoE review session for each.

1. Use the read-only GitHub MCP notification tool to list notifications with `filter: "include_read_notifications"`, following every page until exhausted. This includes requests even if their notification was read. Inspect notification details as needed. Include only notifications whose reason is `review_requested` and whose subject is a pull request. Do not treat review comments, review submissions, mentions, or other notification reasons as requests. Preserve the canonical base repository `owner/repo`, pull-request number, title, and URL. Confirm the PR remains open and the requested reviewer is still listed using the GitHub MCP `pull_request_read` tool's `get` method. If the notification or PR data does not establish these fields unambiguously or confirm an outstanding request, skip it and report why.
2. Run `aoe list --json` once for the batch. For each request, check whether an AoE session already has worktree branch `attention/pr-<number>` for that repository. Treat any existing session state as already handled; do not create another session for an archived or trashed review either. The full base repository identity matters because pull-request numbers repeat across repositories.
3. For each request with no existing session, invoke the existing `attention-session github` command with an empty repository-path argument, the PR number, branch `attention/pr-<number>`, a stable title containing the repository and PR number, a prompt asking the new session to review that PR, an empty additional-prompt argument, and the canonical `owner/repo`. Example shape: `attention-session github '' 123 attention/pr-123 'review owner-repo PR 123' 'Review PR owner/repo#123. Inspect the complete change and relevant code; report only actionable findings with file/line evidence. Do not post a GitHub review or otherwise modify GitHub.' '' owner/repo`.
4. `attention-session` resolves the repository against AoE's registered projects, verifies its GitHub origin, fetches the PR head, and creates or resumes the matching review worktree. If it fails, report the repository and PR; do not fall back to another repository, scratch session, or direct session-creation command.
5. Process each distinct repository/PR at most once per run. Report sessions created or resumed, skipped existing sessions, and failures. Do not mark notifications read, submit reviews, post comments, or perform other GitHub writes.
